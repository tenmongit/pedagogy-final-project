# Izden — бэкенд

FastAPI + SQLAlchemy + SQLite. Реализует разделы 4–6 и 8 спеки (`CLAUDE.md` в корне). Интерактивная документация эндпоинтов: `http://localhost:8000/docs`.

## Запуск локально

```bash
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload     # http://localhost:8000
pytest                            # тесты
```

Чтобы фронт ходил в этот бэкенд, в `frontend/.env.local`: `VITE_USE_MOCKS=false` и `VITE_API_URL=http://localhost:8000`.

## Демо-данные

На пустой базе создаются: преподаватель, три студента и одно задание. У Daniyar работа на финале с историей версий, фидбэка и подсказок, у Aigerim на черновике, у Aliya работы нет. Тексты работ на английском, данные совпадают с моками фронта.

Подсказки в сиде — настоящие ответы модели на эти вопросы, получены через тот же код и промпты, что на сайте; вручную не правились. Они лежат в `app/seed_hints.json` вместе с моделью и временем генерации. Если промпты или тексты сида заметно изменятся, перегенерировать: `python -m scripts.seed_hints` из каталога `backend` (9 вызовов ИИ, нужны `AI_API_KEY` и `AI_MODEL` в `.env`). Сбросить базу к сиду: удалить файл `izden.db` (в Docker: том `izden-data`) и перезапустить.

## Вход

Паролей нет (раздел 4 спеки). `GET /api/users/demo` отдаёт список пользователей, `POST /api/auth/login` с `{"user_id": 1}` возвращает `token`. Дальше каждый запрос идёт с заголовком `Authorization: Bearer <token>`.

## Эндпоинты

Пути, тела и ответы строго по разделу 6 спеки, расхождений нет. Ошибки всегда в формате `{"error": {"code", "message"}}`; ошибки валидации отдаются как `400`, а не `422`.

Что уточнено сверх спеки:

- Создание задания, работы, версии и фидбэка отвечает `201`, остальное `200`.
- `my_work_id` есть только у студента и только в `GET /api/assignments`.
- Текст версии, вопрос к подсказке, фидбэк и название задания из одних пробелов считаются пустыми (`400`).
- Вход с несуществующим `user_id` отвечает `404`.

## Запуск в Docker

```bash
cp backend/.env.example backend/.env   # заполнить JWT_SECRET и CORS_ORIGINS
docker compose up -d --build           # только API на порту 8000
```

База лежит в томе `izden-data`. Без `JWT_SECRET` в режиме `ENV=production` сервер не стартует. Публичный деплой вместе с фронтом описан в [deploy/README.md](../deploy/README.md).

## ИИ-модуль

Для демо без поставщика ИИ оставьте на фронтенде `VITE_USE_MOCKS=true` и `VITE_AI_DEMO=true`.
Интерфейс помечает заготовленные подсказки и вопросы «Демо / в разработке».

Для вызовов модели настройте `AI_API_KEY` и `AI_MODEL` в серверном `.env`. Если API
провайдера отличается от OpenAI, укажите `AI_BASE_URL` сервиса, который поддерживает
Chat Completions с `max_completion_tokens` и JSON mode. Для локального сервера используйте
`uvicorn app.main:app --env-file .env`. Без настроенной модели ИИ-маршруты возвращают
`502 AI_UNAVAILABLE`.

Чтобы работать через Claude, в `.env`:

```
AI_PROVIDER=anthropic
AI_API_KEY=sk-ant-...
AI_MODEL=claude-opus-5-5
AI_MAX_TOKENS=4000
AI_EFFORT=low
```

`AI_BASE_URL` в этом режиме не используется. У Claude `AI_MAX_TOKENS` включает размышления
модели, поэтому 800 мало: ответ обрежется и вернётся 502. Отказ модели, обрыв по лимиту
токенов, таймаут и ошибки API тоже дают 502 и идут в суточный лимит. Прогон примеров:
`python -m scripts.check_ai` из каталога `backend`.

`AI_DAILY_LIMIT` ограничивает попытки вызова подсказок и защиты суммарно за сутки UTC.
Счётчик сохраняется в отдельном файле SQLite рядом с базой бэкенда. При необходимости
путь задаётся через `AI_QUOTA_DB`. На этап доступно 10 успешных подсказок на студента.

Генерация живёт в `app/ai/service.py`, маршруты `/api/works/{id}/ai/*` в `app/routers/ai.py`:
они проверяют права, собирают контекст, сохраняют лог подсказок со снимком текста и вопросы
с `why` и `edited_by_teacher`. Когда модель настроена на сервере, фронт собирается с
`VITE_AI_DEMO=false`, чтобы снять плашку «Демо» (см. `deploy/README.md`).

Примеры и порядок проверки качества описаны в [docs/ai-tests.md](../docs/ai-tests.md).
